# Jev／d1 配對評測與四象限留牌分析

日期：2026-10-02（台灣時間）。使用者已停止排位；本次只做離線分析與有預算上限的模型 API 比較，沒有啟動新局、改正式模型或改留牌規則。

## 結論

目前沒有支持全面換成 Liquid d1 的證據。現行規則、搜尋與模型串接下，12 個交給模型的既有裁定盤面，Jev 得 8 分、d1 得 7.5 分；Jev 的延遲也較低。這是開發回歸資料，不是盲測、整回合品質或實戰勝率證明。

四象限已能從實戰紀錄重建，但控制對局總共只有 5 場；每卡、每組合樣本更少。先保留透明統計，不能把這些觀察值直接改成正式留牌權重。

### 使用者指出歷史樣本範圍後的更正

上述四象限只用了最新兩批，不能代表專案全部歷史資料。分析程式明確固定了兩個 runs，較早對局未納入；這是分析範圍漏選，不是已檢查歷史後認定只有 26 場能用。

重新盤點本機 Deck Tracker 的 DeckStats.xml／DefaultDeckStats.xml：共有 269 個不重複 GameId，包含不同職業、模式及人工對局；其中已標記 Warlock＋Wild＋Ranked 的 196 場，均屬同一 DeckId，131 勝 65 敗。196 場從 2026-08-28 開始，並非全由 Jev 執行，也不能全歸給新版；2026-09-29 起有 171 場。另有一筆狂野排位缺英雄欄位，未擅自算入術士。runtime 保存 1–180 號舊批次操作 log，操作次數也不能直接當成不重複完成對局數。

因此使用者所說「約 250 場」接近帳戶所有模式的歷史總量，但目前核實不到 250 場同牌組、同用途的完整留牌樣本。歷史範圍確實比前表大；擴充四象限應逐局對齊勝負、起手回報、對手分類及版本，分別呈現歷史留牌分析與新版表現。這次盤點尚未完成全部歷史起手／象限重建，原四象限數字仍僅適用最新兩批。

盤點來源 SHA256 與安全彙總保存在 `eval/runs/history-inventory-2026-10-01T18-41-24-691Z/inventory.json`，未改寫原凍結結果。

繼續累積個案修補確實可能邊際效益遞減。200 多個測試不等於 200 多個獨立、有裁定的真實策略盤面；這次模型比較使用 16 個既有開發裁定，兩次重複也沒有增加獨立樣本。下一步應按共通失誤機制改進，而以未參與修改的新盤面檢驗是否泛化。

### 方法限制與修正紀錄

- 題目是已用過的開發裁定，不是未見資料。部分候選由裁定資料恢復，含 synthetic 候選，不能宣稱是原引擎完整合法選單。
- 只裁定計畫第一步，沒有裁定完整計畫。固定候選直接比較與現行完整流程是不同問題，不能混算。
- 先前 `model-pair-2026-10-01T18-09-30-081Z` 漏了 constrainActions；其 pipeline 分數不作正式流程結論。原結果保留，修正後建立上述新批次，没有覆寫。
- 正式批次有收據費用 US$0.02682656；含先前探索批次，總已記錄收據費用 US$0.056095016。timeout 無費用收據，不能宣稱該次免費。
- 模型 Gateway ID 是別名，回覆未提供可鎖定的供應商權重 checkpoint。可以固定輸入及候選重跑，無法保證未来模型答案相同。

## 四象限與每卡留牌

正式資料是 `eval/runs/mulligan-cohorts-2026-10-01T18-26-48-155Z/`。兩批正常完成合計 37 場、19 勝 18 敗；其中 36 場可核實起手保留 receipt 與先後手。1 場缺完整 receipt，10 場對手類型未知；26 場可以依已公開牌推定廣義控制／其他類型。

| 對手類型 | 先手：勝／場 | 後手：勝／場 |
|---|---:|---:|
| 控制 | 0/2（0%） | 0/3（0%） |
| 其他（快攻、節奏、可辨識 combo） | 5/8（62.5%） | 5/13（38.5%） |

控制先手 0/2 的 95% Wilson 區間約 0–65.8%；控制後手 0/3 約 0–56.2%。不能把 0% 解讀成真實對局勝率為零。含未分類的 36 場，先手 9/14（64.3%），後手 9/22（40.9%），同樣不能據此斷言硬幣／留牌策略造成差距。

`report.md`、`stats.json` 已分四格列出每卡起手出現場數、刻意保留場數／勝場、保留率、保留勝率、95% 區間與相對該格平均差值，也分析既有三組留牌搭配。每卡按場計數，雙份不重複增加樣本。只計伺服器確認留下的原起手卡，不混入換入卡。

留牌分析的限制：

- 勝負來自批次保存的正常完成狀態；保留卡來自 Power.log 的同局、同玩家完整回報。故障局與使用者中止局未混入正常策略樣本。
- 對手類型是事後依公開出牌推定，附 evidence／rationale，沒有完整對手牌表。未知不塞進「其他」。較快結束的勝局更容易未知，會有分類偏差。
- 這些事後分類不能提供給即時留牌程序；開局只能用當時已知訊息或對手類型的機率分布。
- 留牌與換牌並非隨機分派，兩組還會受起手組合、對手、先後手等影響；保留勝率高低不是保留該卡的因果收益。
- 分象限後每卡最多僅數場，尚不足調權重。現有截圖來源 mulligan.json 沒有象限與樣本數，不能拆造數字。
- 外部大樣本尚未取得：[HSReplay G-V2 官方頁](https://hsreplay.net/mulligan-gv2/) 當次只支援標準；[HSGuru 狂野術士頁](https://www.hsguru.com/decks?format=1&player_class=WARLOCK) 公開抓取回覆 403。本次沒有取得可直接套用此牌表的外部四象限留牌表。

## 可重跑命令

在專案根目錄使用 Node；所有輸出建立新時間戳目錄，不覆寫原資料。排位不會啟動。

```powershell
# 重建候選、檢查公開價格與保守預算，不呼叫模型
node --env-file-if-exists=.env.local src/eval-model-pair.mjs

# 使用正式批次的凍結請求驗證 SHA256；不呼叫模型
node --env-file-if-exists=.env.local src/eval-model-pair.mjs --replay eval/runs/model-pair-2026-10-01T18-20-41-240Z

# 加 --live 才呼叫兩個模型；預設 5 秒 timeout、US$0.25 預算上限
node --env-file-if-exists=.env.local src/eval-model-pair.mjs --replay eval/runs/model-pair-2026-10-01T18-20-41-240Z --live

# 从保存對局及原始 session Power.log 重建象限（需原始來源仍在）
node src/eval-mulligan-cohorts.mjs

npm test
```

象限的凍結 `games.json`、`matchup-annotations.json`、`stats.json` 與 manifest 足以檢查當次分析。若原始 session 搬移，重建程序會需要原來源路徑；不要換一份 log 冒充相同來源。保留舊標註，新裁定應另立版本。原模型回覆也已保存，可不再付費重新核對評分。

## 下一步方向

優先改進「取得資訊後重新規劃、召喚後能否存活、資源花費與後續可行動作」這些共通表示，避免繼續用 game ID 特判。先用既有失敗建立機制假說，再在修改前收集並裁定未用過的盤面，以相同合法候選配對驗證；同時保留舊盤面防回歸。評分以盤面為單位，報告不確定性，不能用重複呼叫膨脹樣本。

若仍要測更強 AI，應另建語言模型選擇器，在相同候選上量測額外收益、延遲與每局費用，尤其檢查上述共通錯誤是否改善。本次只測 d1，沒有證據推論其他語言模型一定較好。

RL 暫排後面：現有模擬對未知抽牌、隨機效果與未涵蓋卡效仍會停止重觀察，不能直接當成完整自我對弈環境。較小的下一階段可以是通用特徵上的候選排序器，但需要足量、可靠且與測試集分開的比較標籤。訓練前先證明評測能辨識進步；284 項測試通過本身不是棋力增長。
