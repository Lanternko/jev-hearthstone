# 第 3 場 Eswin：第二張 buff 不能排在攻擊之後

這張截圖確實顯示錯誤順序。它來自已停止批次 `ranked-2026-10-03T17-42-01-535Z` 的第 3 場、我方第 2 回合（engine turn 3），row8387，原決策時間 `2026-10-03T17:56:11.799Z`，使用 `silverfish-v1-combo-admission-v2`。不是目前 shield-alternatives-v1 修正後的新實戰。

## 原始執行

原盤面有四隻可攻擊手下，2 費，手上是 1 費混亂連鎖、1 費低語及 2 費侍僧。原 p1 先打混亂連鎖，再依序用 Walking Dead、Felbeast、Party Fiend、Felbeast 打臉，最後才另打一張低語。原 log #6～#11 可對照。

截圖顯示對方 33 血、我方還有 1 費：原計畫已完成混亂連鎖及前三次攻擊，最後一隻 Felbeast 尚未攻擊。低語此時仍應先出，更理想的順序是在第一次攻擊前就打低語，棄掉侍僧、處理隨機召喚與 buff，再根據實際盤面攻擊。四隻原有手下均可取得第二次 +1/+1；不能預設兩隻隨機召喚的身分、攻擊資格或 buff 適用性。

舊程式當前選單會延後攻擊，但接續佇列只檢查盤面簽章與合法選项。因此「已经打過一張 buff」的計畫仍能一路接續攻擊，繞過剩下那張 buff。這與先前第 2 場修正的佇列缺口相同。

## 本次確認

目前版本沿用先前的 turnOrderAssessment／allowsPlanContinuation 修正。從原始紀錄的確定第一步推導、重新觀察後：

1. 盤面簽章與舊計畫第二步完全相同，舊攻擊也合法，單靠這兩個條件抓不到錯誤。
2. 新接續檢查拒絕該攻擊，清除舊佇列，重新規劃時選擇先打低語。
3. 低語棄掉侍僧觸發隨機召喚，模擬標成不確定結果，停止於單一動作；不捏造召喚身材、不預排後續攻擊。
4. 原計畫前三次攻擊後的截圖狀態也通過相同檢查，剩下攻擊必須先等低語。

本次沒有修改執行程式，也沒有增加卡名例外或另發一個版本。已存在的修正能涵蓋此局，但在這張截圖出現前未單獨保存這個「連續兩張 buff、第二張觸發隨機召喚」案例。
