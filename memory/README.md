# 共用記憶（memory/）

所有 agent（Claude Code、Codex、雲端專案 thread）**只透過這個資料夾溝通**。不靠對話交接：要交給別的 agent 的事，一律寫進 `handoff.md` 或對應欄位檔。
記憶不是逐日敘述，而是固定欄位的條目。2026-10-27 以前的逐日紀錄已拆進下面五個檔，原文保留在 [archive/STATUS-2026-10-27.md](archive/STATUS-2026-10-27.md)（只讀歷史，不再寫入）。

## 開工必讀順序

1. `handoff.md`（現在在做什麼、下一步）
2. `lessons.md`（不要再犯的錯）
3. `rulings.md`（使用者的裁定，出牌邏輯不得違反）
4. 其餘按需查：`grep -n "關鍵字" memory/findings.md memory/experiments.md`

## 寫入規則

- **只追加新 ID**：新條目接在檔尾，ID 取該檔目前最大號 +1。不重編號、不刪條目。
- **一筆一件事**：一個發現、一次實驗、一條裁決、一個教訓各一筆；彼此用「相關」欄位互指（例如 `F-012、E-034`）。
- **狀態改變時改原條目**：只改「狀態」欄，括號註明日期與原因，例如 `被推翻（2026-11-02，E-210 重跑後 49.8%）`；同時寫一筆新條目說明新證據，兩筆互指。
- **數字照量到的寫**：證據欄寫指令、檔案路徑與數字；沒量過的寫「待驗」，不要寫成已證實。
- **抓到錯誤就寫 lesson**：每個被抓到的錯誤（使用者指出的、測試抓到的、自己發現的）寫成一筆 lesson；能自動檢查的就加測試，把測試檔寫進「對應測試或關卡」。
- **收工**：新發現、實驗、裁決、教訓各寫進對應檔，然後**覆寫** `handoff.md`。
- 欄位定義與範例寫在各檔檔頭。
- 「來源」欄：從舊 STATUS.md 搬來的條目指向 `archive/STATUS-2026-10-27.md` 的行號；新條目可寫 commit、log 路徑或對話來源，沒有就省略。
