所有 agent（Claude Code、Codex、雲端專案 thread）**只透過這個資料夾溝通**。不靠對話交接：要交給別的 agent 的事，一律寫進 `handoff.md` 或對應欄位檔。

## 開工必讀順序

1. `handoff.md`（現在在做什麼、下一步）
2. `lessons.md`（不要再犯的錯）
3. `rulings.md`（使用者的裁定，出牌邏輯不得違反）
4. 其餘按需查：`grep -n "關鍵字" memory/findings.md memory/experiments.md`

## 寫入規則

- **只追加新 ID**：新條目接在檔尾，ID 取該檔目前最大號 +1。不重編號、不刪條目。
- **一筆一件事**：一個發現、一次實驗、一條裁決、一個教訓各一筆；彼此用「相關」欄位互指（例如 `F-012、E-034`）。
- **狀態改變時改原條目**：只改「狀態」欄，括號註明日期與原因，例如 `被推翻（2026-11-02，E-210 重跑後 49.8%）`；同時寫一筆新條目說明新證據，兩筆互指。
- **數字照量到的寫**：證據欄寫指令、檔案路徑與數字；沒量過的寫「待驗」，不要寫成已證實。
- **抓到錯誤就寫 lesson**：每個被抓到的錯誤（使用者指出的、測試抓到的、自己發現的）寫成一筆 lesson；能自動檢查的就加測試，把測試檔寫進「對應測試或關卡」。
- **收工**：新發現、實驗、裁決、教訓各寫進對應檔，然後**覆寫** `handoff.md`。
- 欄位定義與範例寫在各檔檔頭。
- 「來源」欄：從舊 STATUS.md 搬來的條目指向 `archive/STATUS-2026-10-27.md` 的行號；新條目可寫 commit、log 路徑或對話來源，沒有就省略。

## 版本號（2026-10-29 起，R-144；照 basketball-autochess R-018／R-019／R-023）

五條軌道各自編號：`zoo`（warlock-zoo 網路）、`discard`（warlock-discard）、`zakajz`（warlock-zakajz）、`egg`（priest-egg 駕駛，模擬對手）、`sim`（模擬器：`src/sim-version.mjs` 雜湊涵蓋的程式、牌表與卡牌資料）。格式 `0.MINOR.PATCH`；某條網路軌道上了實戰、ranked 批次過 G5 才發 1.0。

| 情況 | 寫法 | 例 |
|---|---|---|
| 實驗（還沒採用） | 基準版本＋`+E編號` | `zoo 0.1.0+E254` |
| 實驗採用，且變強（網路）或更像實戰（sim） | 升 MINOR，PATCH 歸零 | `zoo 0.2.0` |
| 實驗採用但沒有變強：換模擬器版本重訓、encoder 旗標、重新匯出、修 bug、補卡牌規則 | 升 PATCH | `egg 0.1.1` |
| 只更新資料（sim 軌道：牌表、卡牌資料、對手 prior），規則程式與模型都沒動 | 加字母後綴，z 之後接 aa | `sim 0.1.0a` |

- 實驗不佔版號：失敗的只留 E 條目。平行實驗掛在同一個基準上（`egg 0.1.0+E261A`、`+E261B`），不假裝彼此有先後。
- 多個實驗一起採用時合成一版，在 R 條目寫明「0.2.0 = 0.1.0 + E-xxx + E-yyy」。
- 模擬器雜湊（12 碼）仍是 G2 契約、比較只看雜湊（G3）；sim 版本號是給人看的標籤，R 條目寫「sim 0.1.0 = 38f4c93a3f4b」。雜湊變了就至少是一個字母或 PATCH。
- 舊檔名（`warlock-zoo-v10`、`priest-egg-pilot-v6-20261028` 等）不改名，對照見 R-144。新採用的網路匯出成 `models/selfplay/<牌組>-<版本>.{pt,json}`（例 `warlock-zoo-0.2.0`）；實驗輸出目錄用 `runtime/<軌道>-<基準>+E<編號>-<短名>/`。

### 各位數什麼時候升

判斷問題：這次改動有沒有讓網路更強（sim 軌道：更像實戰）？

| 位數 | 升的條件 | 例 |
|---|---|---|
| MAJOR | 實戰依賴的介面改了，舊模型或 encoder 會失效；1.0 前固定 0 | 0→1：上實戰過 G5；1→2：網路輸入格式改了、實戰 encoder 要跟著換 |
| MINOR | 網路：G3 compare PASS，且在沒參與挑選的 seed 上再 PASS（G4），其他對手不退步（每項 compare 不 FAIL）。**進步要來自像實戰的對手**：只對已知比真人弱的模擬對手（例如模擬蛋牧，F-784）變強不算（R-145），那樣最多 PATCH。sim：實戰對模擬的比對（`src/opp-likeness.mjs` 等）樣本外更接近 | 對 shaman／zakajz／dh／鏡像都顯著變強 |
| PATCH | 採用了但沒有變強（含只對弱模擬對手變強，例：zoo-v10）：換模擬器版本後重訓到同強度、加 encoder 格（pile、imbue）、重新匯出、修 bug；sim 補卡牌規則或修規則 | R-141 規則補完 |
| 不升 | 輸出完全沒變 | 重構、註解、報告排版 |

- 不採用里程表式進位：0.1.9 之後是 0.1.10。上一位升了，下面歸零。
- 一次發版只升一位，取影響最大的那個。
- 升 MINOR 要過 G1–G4，網路軌道要上實戰的再加 G5；升 PATCH 過 G1–G3。
- 批次發版：過門的實驗先排隊，使用者決定採用後合成一版。數字長太快通常是把實驗當成發版。
- 跨軌道各自升版，相依寫在 R 條目，例如「zoo 0.2.0 需要 sim ≥ 0.1.0」。網路的 `sim` 欄位就是它的 sim 相依。
