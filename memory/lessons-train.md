## 啟動與監看

### L-044 5090 長工作：啟動、監看、收結果
- 日期：2026-10-25～2026-10-30
- 發生什麼：
  1. 5090 上的等待迴圈用 `pgrep -f` 比對到自己的指令，變成三個永遠不會結束的迴圈；遠端 `pkill -f "run_v10.sh"` 比對到 ssh 自己的 bash -c，把自己的連線殺掉（exit 255）。（L-031、L-045）
  2. 一條 ssh 同時 `nohup … &` 再 `sleep; tail`，本機 ssh 一直不返回。（L-044、L-059）
  3. 啟動指令被斷線打斷後以為沒啟動又啟動一次，兩組訓練同時寫同一目錄。（L-045）
  4. 接續訓練時以為 --opp 檔就是對手，其實被 checkpoint 存的對手蓋掉，v9 整輪沒對到 P2；log 第二行就寫了卻沒看。（L-045）
  5. 訓練還在跑時就匯出了跑到一半的 policy.pt。（L-037）
  6. E-298 11:40 就寫了 DONE，App 的背景監看只等到「開跑」就退出，到 18:20 使用者問了才發現。（L-083）
  7. 在 5090 同步目錄跑全套 npm test 有 28 題失敗，原因是缺 memory／eval／新模型／git 歷史，不是程式錯。（L-080）
- 規則：
  1. 啟動用一條只負責啟動的 ssh：`nohup … > log 2>&1 < /dev/null &` 後立即結束（或 `ssh -f`）；不要在同一條 ssh 裡 sleep 等。
  2. 啟動後立刻讀 log 開頭，確認對手／resume 來源符合預期；resume 時要換對手加 `--opp-fresh`。等第一輪 log 出現再離開。
  3. ssh 失敗後重新啟動前先看是否已在跑；殺程序用 PID（先 `ps -eo pid,args`），不用會比對到自己命令列的 `pkill -f`／`pgrep -f` 樣式。
  4. 完成判斷靠腳本最後 touch 的 DONE／FAILED 旗標。開跑後起一個背景指令（`run_in_background`，`train/await-5090.sh`）在遠端迴圈等 DONE 或 FAILED 才退出，只喚醒一次；這不算輪詢。
  5. 評估與匯出等最後一輪跑完才做，不用跑到一半的 checkpoint。
  6. 同步目錄的測試閘門用 `test/selfplay-*.test.mjs` 加相關 Python 測試並比對 sha256；全套 npm test 在本機跑。連線方式照全域 CLAUDE.md（Tailscale）。
- 對應測試或關卡：`train/test_opp_fresh.py`（只涵蓋第 2 點）；`train/await-5090.sh`（寫進 role-train skill 的啟動步驟）
- 相關：F-686、F-857、E-225、E-253、E-254、E-298
- 合併自：L-031、L-037、L-044、L-045、L-080、L-083

### L-059 腳本路徑與預註冊
- 日期：2026-10-29
- 發生什麼：
  1. E-273 的 `run.sh` 放在 `runtime/<名>/`，`cd "$(dirname "$0")/.."` 只回到 `runtime/`，因為 `cd` 成功，後面的 fallback 也不生效；開跑前才發現並重算腳本 sha256。（L-059）
  2. E-272 預註冊記了 `fit_value.py` 的 sha256，第一次跑就因 numpy 一次吃整批 obs 記憶體不足而必須改，sha256 跟著變。同時本機可用記憶體約 10 GB，整份 `npm test` 出現 WinError 1455 假失敗，數量每次不同。（L-060）
- 規則：
  1. 放在子目錄的腳本要回根目錄時數清楚層數（`/../..`），真跑前先看 `out/jobs.txt` 與第一個輸出檔確認路徑。
  2. 預註冊前先用最大資料量實際跑過載入與前向一遍（不看結果），確認記憶體夠再凍結 sha256；腳本一改就重算 sha256 並同步預註冊；預註冊後才改的，在結果裡寫「改了什麼、為什麼不影響數值、新舊 sha256」。
  3. 本機 `npm test` 出現 WinError 1455 或 node 異常退出碼時，逐檔重跑失敗的測試並如實寫「環境失敗」，不要當成程式錯，也不要當成全過。

### L-025 搜尋與蒸餾的目標
- 日期：2026-10-12～2026-10-24
- 發生什麼：
  1. 搜尋評分不夾上下界，未結束盤面的估值蓋過真正的獲勝（漏斬殺一度 31.3%）；未走完的路線拿期望值和走完的結果直接比。（L-025）
  2. 策略目標只用搜尋分數的 softmax，2 輪後對起點只剩 44%。（L-026）
  3. 搜尋只在價值網路熟悉的對局有用，放進沒練過的牌組組合反而變差。（L-029）
- 規則：
  1. 搜尋比較路線時，估值夾在界內（±0.98）；沒走完的路線排在走完的之後，不和走完的結果混比。
  2. 蒸餾目標要乘上網路原本的機率（原機率 × exp(搜尋分數 ÷ tau)）。
  3. 蒸餾不放進沒練過的牌組組合。拿 value 頭估局面的條件見 L-065。
- 對應測試或關卡：無
- 相關：F-497、F-498、E-122、F-613、L-065
- 合併自：L-025、L-026、L-029

### L-065
- 日期：2026-10-29
- 發生什麼：前瞻搜尋把「輪到對手」的局面交給被測網路的 value 頭從對手座位估再變號；zoo 0.2.0 只用 `--opp`（對手是另一個網路）練了 405 輪，value 頭不會估對手座位，E-277 量到 look −38.2 分就判「到頂」。換成從自己座位估後回到 −1.3（E-286）。第一版只把座位換過來，沒把這回合剩下的 mana 與沒攻擊的手下清掉，網路把「留著沒用」看成「新回合開始」，搜尋改成提早結束回合（本機 0.2.0 15/60、v10 18/60）。
- 以後一律：搜尋或任何拿 value 頭估局面的地方，送進去的局面要和 value 頭訓練時看過的一樣：座位要是它練過的座位（`--opp` 訓練的網路只用學習方座位，`--own-value`），而且交手後的局面要顯示成「這回合已用完」（`seatView`）。換網路或換訓練方式（加減 `--opp`、鏡像）後，前瞻結果先跟同網路 plain、別的網路 look 對照，崩了先查估值座位，不直接下「沒空間」的結論。
- 對應測試或關卡：`test/selfplay-search-own-value.test.mjs`（ownValue 下送出的狀態全部是學習方座位、mana 0、無人可攻擊）；headroom 量測用 `--own-value`，`--json` 的 look 欄 `a+own` 與舊量尺不混比。
- 相關：F-882、E-277、E-286、E-275
