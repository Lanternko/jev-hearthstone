# 經驗教訓（lessons）

做事方法、流程與量測方法的教訓。每個被抓到的錯誤寫一筆；能自動檢查的就加測試。讀寫規則見 [README.md](README.md)。

**2026-10-30 整併與拆檔**：同主題的教訓合成一條（ID 沿用該組最小或最核心的那號，`合併自` 列出舊 ID），過時的刪掉；並依工作範圍拆檔。這份是通則，**每次開工都讀**；其餘只有工作碰到那個範圍時才讀：
- [lessons-train.md](lessons-train.md)：訓練、`train/ppo.py`、5090 長工作。
- [lessons-live.md](lessons-live.md)：實戰客戶端、ranked 批次、斷線重連、點擊幾何、賽後做位置題。
- [lessons-jev.md](lessons-jev.md)：Jev＋`src/describe.mjs`／`src/policy.mjs` 時代（棄牌術）。
- [lessons-ids.md](lessons-ids.md)：每個 L-ID 在哪個檔；被併掉或刪掉的舊 ID 也查這裡。

新教訓照範圍寫進對應的檔；ID 全域共用，寫入前一刻取所有 `lessons*.md` 目前最大號 +1（L-057），並補進 lessons-ids.md。跟現有條目同主題時優先在那條加一點，而不是開新條。

欄位（固定）：
- **ID**：`L-001` 起，只追加，所有 lessons 檔共用一個號碼序列。
- **日期**
- **發生什麼**
- **規則**：以後一律怎麼做。
- **對應測試或關卡**：測試檔、評估門檻或流程關卡；沒有寫「無」。
- **相關**：其他 ID。
- **合併自**（合併條目才有）
- **來源**（選填）

範例：

```
### L-999
- 日期：2026-10-27
- 發生什麼：guard 只比對 PLAY，但實戰出牌選項的 type 是 POWER，guard 從沒觸發，模擬測試卻全綠。
- 規則：guard 的測試要用 decisions.jsonl 的真實選單當輸入，不能只用手寫的選項。
- 對應測試或關卡：test/net-guards.test.mjs
- 相關：F-999
```

### L-030 門檻評估：怎麼量、怎麼報、怎麼存
- 日期：2026-10-12～2026-10-28
- 發生什麼：
  1. 評估取最先結束的 N 局會偏向短局。（L-023）
  2. 量搜尋對各副牌的貢獻時，用同一批種子、先後手各 1000 局，並和另一條獨立量法（Python 55.0%）對照才信。（L-028）
  3. shaping 訓練的盤面分數預測更準，鏡像對打反而比純 PPO 差；單一局面勝率差大（Kazakus 0.17 vs 0.61）不代表整體變強。（L-030）
  4. v5 是 5 組挑 1 組，有選擇偏差；之後新版本對 v5 約 50% 不代表沒用。（L-034、L-035）
  5. 比較新舊模型時，兩邊數字常是不同模擬器版本或不同 guard／seed 跑的，直接相減。（L-046）
- 規則：
  1. 評估新訓練版本一律對固定參照打先後手各 1000 局、每桌一樣多局；門檻是鏡像 ≥53% 且 Wilson 區間不含 50%。不以單一局面或預測準度取代對打勝率。
  2. 比較一律用 `node src/selfplay-compare.mjs`，兩邊用同一份程式碼重跑 `selfplay-match.mjs --json`，盡量給多個 seed（間距見 L-036）；它拒絕（exit 2）就重跑，不要手算繞過。
  3. 只存過門檻的版本；沒過就不匯出、舊版繼續用。所有組別都報告，不事後挑選。
  4. 解讀時考慮基準版本本身是挑過的：「持平」不是「無效」、「微輸」不是「有害」；只有 2 個 seed 時只下「沒證據」的結論。
  5. 用兩種量法量同一件事時，數字要一致才信。
- 對應測試或關卡：`test/sim-version.test.mjs`（G3 拒絕條件）；`runtime/zoo-v5-eval/gate.txt`
- 相關：E-154、E-176、E-199、F-480、F-730、F-735、F-858、L-036、L-010
